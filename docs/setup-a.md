# A/controller setup

Local source setup and demo need no account configuration; use README.
The controller origin in the example is a placeholder. Keep controller and
upstream within one verified runtime/network context. Native setup is gated by
[user-actions.md](user-actions.md); don't assume executor localhost is the
cloud-desktop listener. Use only a hub-producer with read/submit on all three
queues, never B/C work credentials. See [controller prompt](../prompts/dot-a-controller.md).

After B and C work, A's distinct synthesis identity gets read/work/subscribe on
dot-a only. Discover tools, connect through verified authenticated routing,
approve the queue subscription and verify the actual main-conversation return.
See [synthesis prompt](../prompts/dot-a-synthesis.md). Controller MCP is not yet
implemented; source CLI is the supported management interface.
